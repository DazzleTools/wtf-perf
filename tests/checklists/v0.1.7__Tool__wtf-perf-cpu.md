# Human Test Checklist: `wtf-perf cpu`

**Target version:** 0.1.7
**Ships with commit:** feat(cpu): bare wtf-perf runs cpu; root manifest for wtf-windows; human checklist (0.1.7)
**Companion automated tests:** 53 in `tests/test_cli.py` (13), `tests/test_sampler.py` (14), `tests/test_counters.py` (5), `tests/test_families.py` (6), `tests/test_findings.py` (5), `tests/test_render.py` (3), `tests/test_version.py` (7)

## What this is

The automated tests drive the sampler, ledger and renderer with scripted data. This checklist covers what they cannot: the numbers against Task Manager on a real machine, the terminal output and paging, and the hook-up through wtf-windows. About 15 minutes. Read-only throughout: wtf-perf changes nothing on the machine.

## Prerequisites

1. Windows 10 or 11, Python 3.10 or later.
2. Installed from the checkout: `pip install -e .` in the repository root. Without that install, `wtf-perf` is not on PATH: run every `wtf-perf ...` step below as `python -m wtf_perf ...` with the repository root on `PYTHONPATH`.
3. Task Manager open on the Performance tab (CPU) for section 2.
4. No state to reset: nothing is written except the terminal output.

## High-Value Verification (~5 minutes)

### HV.1 -- The headline adds up

Validates: the ledger accounts for every point of the CPU figure.

- [ ] **Steps:** `wtf-perf cpu -s 15 -np`
- [ ] **Expected:** the VERDICT panel's two detail lines read `headline H = busy B + speed-scaling uplift U` and `busy B = live processes ... + exited processes ... + interrupts/DPCs ... + unexplained ...`, and each line's parts add up to its total (to within 0.1, from rounding).
- [ ] **Why this matters:** this is the question the tool exists to answer.

### HV.2 -- The headline matches Task Manager

- [ ] **Steps:** run HV.1 while watching Task Manager's CPU percentage.
- [ ] **Expected:** the ledger's "Headline (what Task Manager shows)" sits within the range Task Manager displayed during those 15 seconds. "Busy time" is lower when cores run above base speed; the "ratio" column says by how much.
- [ ] **Why this matters:** if the headline does not match what the user sees, the whole account is about a different number.

### HV.3 -- Applications are rolled up

- [ ] **Steps:** with several applications running that spawn helper processes (Claude Code, VS Code, a browser), run `wtf-perf cpu -s 10 -np -t 1`.
- [ ] **Expected:** "Applications (process families)" shows each application once with a process count well above 1; hook processes (`bash`, `git`, `node`, `python`) started by an application are counted under it, not as their own families; a `pwsh` you opened yourself is its own family.
- [ ] **Why this matters:** an application made of many small processes never ranks in Task Manager; this table is where it shows.

### HV.4 -- Short-lived processes are counted

- [ ] **Steps:** in a second terminal, run a loop that starts short processes (cmd.exe: `for /l %i in (1,1,200) do @cmd /c exit`; PowerShell: `1..200 | % { cmd /c exit }`; POSIX shells on Windows: `for i in $(seq 200); do cmd //c exit; done`), and during it run `wtf-perf cpu -s 10 -np -t 1`.
- [ ] **Expected:** "Short-lived processes" reports a count in the tens to hundreds, `cmd` among the images.
- [ ] **Why this matters:** these processes are invisible to any end-of-window process list, and their CPU is part of the headline.

### HV.5 -- JSON for scripts

- [ ] **Steps** (same in every shell): `wtf-perf cpu -s 3 --json | python -c "import json,sys; d=json.load(sys.stdin); print(round(d['reconciliation']['unexplained'],2), round(d['window']['self_cost_pct'],2), d['verdict']['type'])"`
- [ ] **Expected:** three values print; the first is the unexplained remainder in points, the second wtf-perf's own cost (expect under 2), the third the verdict type.
- [ ] **Why this matters:** `--json` is the contract scripts and the AI summary read.

## Section 1: Output and paging

### 1.1 Bare command

- [ ] **Steps:** `wtf-perf`
- [ ] **Expected:** a spinner ("Sampling every process for 10 s...") for about ten seconds, then tier 0 (header, VERDICT, ledger table, findings) and a prompt "Press any key for evidence details, q/Esc to quit...".

### 1.2 Paging keys

- [ ] **Steps:** at the prompt from 1.1, press a letter other than q; at the second prompt press `q`.
- [ ] **Expected:** the first key shows tier 1; `q` ends without tier 2. Repeat with `Esc`: same as `q`.

### 1.3 Tier selection

- [ ] **Steps:** `wtf-perf cpu -s 3 -t 0`, then `wtf-perf cpu -s 3 -t 1,2 -np`, then `wtf-perf cpu --tier 7`
- [ ] **Expected:** only tier 0; tiers 1 and 2 without pauses and without the verdict; an error naming the valid tiers, exit code 2, and no spinner (it refuses before sampling).

### 1.4 From another directory

- [ ] **Steps** (pick your shell): cmd.exe `cd /d %TEMP% && wtf-perf list`; PowerShell `cd $env:TEMP; wtf-perf list`; POSIX `cd /tmp && wtf-perf list`
- [ ] **Expected:** the tool list shows `cpu`.

### 1.5 Known cosmetic gap

- [ ] **Steps:** `wtf-perf cpu -s 3 -np > out.txt` in a console whose code page is not UTF-8, then view `out.txt`.
- [ ] **Expected (known):** exit code 0 and a complete report; tables wrapped to 80 columns, and `?` where a character (an ellipsis, a box-drawing line) has no equivalent in the code page. Before 0.2.0 this crashed with `UnicodeEncodeError`. A real terminal is not affected.

## Section 2: Through wtf-windows

### 2.1 `wtf perf`

- [ ] **Steps** (same in every shell, from the wtf-windows checkout): `wtf mode switch perf --dev --path <path to this checkout>`, then `wtf list`, then `wtf perf cpu -s 3 -np`
- [ ] **Expected:** `perf` appears in `wtf list`; `wtf perf cpu` prints the same report as `wtf-perf cpu`.

## Section 3: Privileges

### 3.1 Elevated and not

- [ ] **Steps:** run `wtf-perf cpu -s 10 -np -t 0` in a normal terminal, then in an elevated one, while the machine is doing similar work.
- [ ] **Expected:** comparable numbers in both; no error in either (the process table and counters need no elevation).

## Section 4: The AI summary (added for 0.1.9 to 0.1.15)

### 4.1 Claude, names only

- [ ] **Steps:** `wtf-perf cpu -s 10 --ai -np`
- [ ] **Expected:** after the findings, a panel titled "AI summary (claude, haiku)" with What happened / Why / What to do / Confidence, naming applications from the families table. No tools are used and no files change.

### 4.2 A local model

- [ ] **Steps:** with LM Studio's server on and a model loaded: `wtf-perf cpu -s 10 --ai lmstudio --ai-only`
- [ ] **Expected:** only the AI panel, titled with the local model's name. With the server off: one line saying the backend is not available, exit code 1 (with `--ai-only`).

### 4.3 Command lines only when asked

- [ ] **Steps:** `wtf-perf cpu -s 5 --ai prompt-only --ai-only`, open the saved prompt file it names; then the same with `--ai-detail full`.
- [ ] **Expected:** the first prompt has process names but no `command_line` fields; the second has them for live processes, "(exited before it could be read)" for exited ones, and -- run without elevation -- "unavailable" for other users' processes. With `--ai claude --ai-detail full`, a yellow note warns that command lines leave the machine.

### 4.4 Saved defaults

- [ ] **Steps:** `wtf-perf cpu -s 3 --ai codex --ai-detail full --ai-save -np -t 0`, then `wtf-perf cpu -s 3 --ai -np -t 0`.
- [ ] **Expected:** the second run uses codex with full detail without being told; `~/.wtf-perf/config.json` holds `"ai": {"backend": "codex", "detail": "full"}`. Reset with `--ai claude --ai-detail names --ai-save`.

### 4.5 Ctrl-C

- [ ] **Steps:** start `wtf-perf cpu -s 3 --ai claude --ai-only` and press Ctrl-C while it waits for the answer.
- [ ] **Expected:** the command ends, and no `claude` process is left running (check Task Manager).

## Section 5: Platforms (added for 0.2.0)

### 5.1 Unchanged on Windows

- [ ] **Steps:** `wtf-perf cpu -s 10 -np -t 0`, and `wtf perf cpu -s 2 -np -t 0` through wtf-windows.
- [ ] **Expected:** the same report as before 0.2.0; `--json` has `"system": {..., "platform": "win32", "provider_set": "windows"}`.

### 5.2 The provider listing

- [ ] **Steps:** `wtf-perf cpu --providers`, then `wtf-perf cpu --platform linux --providers`.
- [ ] **Expected:** four rows (snapshot, counters, command_line, elevation). On Windows all available; for linux all unavailable, each naming the source a port would read. Nothing is sampled (no spinner).

### 5.3 Refusal without sampling

- [ ] **Steps:** `wtf-perf cpu --platform darwin`; on a Linux or WSL shell with the package installed, `wtf-perf cpu`.
- [ ] **Expected:** one line on stderr ("the darwin providers cannot sample here -- snapshot not implemented ..."), exit code 2, returned at once.

## What the automated tests DON'T cover

- Agreement with Task Manager on a real, busy machine
- Terminal rendering, colours, widths and code pages
- Real keypress paging
- The thresholds' fit for machines other than the one they were set on
- Dispatch through a real wtf-windows checkout

## Reporting issues found

1. Note the section and step.
2. Capture the exact command and its output (`--json` output is the most useful).
3. File an issue on the repository referencing this checklist and the version.
